## 6. What broke or surprised me

**The trigger does not call `sc_project_raw_event()` directly.** The work order says it does. `quo_events_project` executes `sc_quo_events_project()`, a zero-argument wrapper, which is what in turn calls `sc_project_raw_event(quo_events)`. The substance is as described; the name in the work order is the inner function, not the one bound to the trigger. Anyone grepping for the trigger by that name will not find it.

**`storeOutboundMessage()` is misleadingly named.** It reads as a `messages` writer and is not one. I nearly removed it under 1.1 and only kept it after reading the body. If 1.1 had been executed on names rather than on reading, outbound SMS capture would have been deleted.

**`quo_events` (1184) exceeds `messages` (1138) by 46.** I did not investigate — `sc_spine_drift` is 0, so by the system's own definition nothing that arrived failed to reach the app, and the gap is presumably events that legitimately project to no message (follow-ups patching an existing row, and the pre-016 event-id collisions). Flagging it because the two numbers are the ones a reader will instinctively compare.

**Nothing else failed.** The `edge-key-source-log` merge was a fast-forward with no conflicts, and the lead-guard patch applied cleanly against the merged file (`git apply --check` passed first).

One process note, since it affected how I worked rather than the result: a naive brace scan for the end of `enrichContact` lands on line 541, which is a `}` inside the prompt template literal, not the function's closing brace. I removed both blocks by asserted anchors — first and last line content checked before cutting — rather than by brace matching.
